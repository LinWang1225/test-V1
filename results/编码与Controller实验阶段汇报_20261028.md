# 渐进式 KV 编码与 Controller 实验阶段汇报

汇报日期：2026-10-28。本文依据仓库当前已完成的编码实验、90 请求 controller 因果回放和 12 请求在线闭环试验整理；不包含新增实验。

## 1. 阶段目标与核心结论

研究目标是：完整保存一份 4-bit KV 编码，在推理时按需读取其 2/3/4-bit 前缀，以较低读取预算维持 attention 输出质量。实验分别回答“如何编码”和“把额外位分配给哪里”两个问题。

目前得到三点阶段结论：

- **编码结构与训练目标均有影响。** 在共享预处理的 19 个完整 4-bit 渐进候选中，JacK_MixV 在 2/3/4-bit 的平均 Attention Output 相对 L2 均最低，相对 Data Tree 改善约 18.0%/21.4%/17.2%。
- **当前 Query 引导的动态读取具有明确的局部数值收益。** 固定原始 Jacobian_Tree，在平均每侧读取 3-bit 的回放中，query_curve 相对均匀读取的真实输出 MSE 降低 42.60%；相对 query_only 的增量为 2.98%。
- **在线闭环已有初步结果，任务收益与系统收益仍待验证。** 12 请求 pilot 中，动态平均 3-bit 的 token 位置一致率高于均匀 3-bit，但逐请求存在明显退化，尚不能宣称稳定改善任务质量或实现推理加速。

## 2. 实验设计与完成情况

模型为 Qwen3-4B，硬件为 RTX 3090 24 GiB、CUDA 12.6。数据覆盖 LongBench 的 qasper、hotpotqa、gov_report、trec、passage_retrieval_en、lcc 六项任务。编码校准使用 60 请求，测试使用 90 请求，原 30 验证请求按既定安排跳过；prompt 最长 8192 token，参考生成 64 步。

|实验模块|当前完成范围|回答的问题|
|---|---|---|
|编码对比|19 个主渐进候选、2 个独立精度参考，另列 KVarN 条件与历史预算包装|相同前缀载荷下，哪种结构和目标更好|
|Controller 因果回放|90 请求，第 0/17/35 层，decode 1/64，四策略、五档预算|同读取预算下，动态分配能否改善真实输出|
|在线闭环 pilot|六任务共 12 请求，每策略 64 步，全部 36 层参与量化 decode|局部决策收益能否传递到生成轨迹|
|正式任务质量与部署性能|尚待补齐|能否改善任务得分、实际带宽和总延迟|

编码主实验覆盖全部 36 层及 decode 1/8/32/64。编码与回放覆盖范围不同，绝对误差不能跨表直接相减。编码实验为单层反事实评估，量化输出不传播到后续层和 token；在线闭环才实际传播量化输出。

## 3. 编码实验：非均匀树与功能敏感性目标表现较好

主比较统一使用固定 Hadamard-sign 旋转和校准 mean/scale，测试时参数冻结。每标量完整保存 4-bit，低精度必须读取同一码字的前缀，不保留 FP16 KV 尾部。统一的是有效载荷，元数据另计。

以下展示代表性候选；指标为平均 Attention Output 相对 L2，越低越好。

|方法|主要特点|2-bit|3-bit|4-bit|
|---|---|---:|---:|---:|
|U_MinMax|极值范围均匀前缀|2.291858|0.757003|0.310456|
|U_Clipped|校准优化范围的均匀前缀|0.568008|0.382779|0.307286|
|Gaussian_Tree|固定高斯先验树|0.572565|0.333256|0.186849|
|Data_Tree|真实 KV 分布的 MSE 树|0.566012|0.304408|0.150318|
|Jacobian_Tree|K output-Jacobian、V attention 权重|0.465620|0.249693|0.136101|
|JacK_MixV|Jacobian K、普通与 attention 混合目标 V|**0.464366**|**0.239342**|**0.124537**|
|Leaf4_Only|先拟合细级，再合并粗前缀|0.557402|0.283912|0.137945|
|TCN_Clipped|优化范围的等宽嵌套分箱|0.565901|0.357856|0.273968|
|Residual211|2-bit 基础码加两级 1-bit 残差|0.576968|0.309098|0.204305|
|LogResidual211|对数压扩后的逐级残差|0.533893|0.374680|0.315570|

**主要观察：** 范围优化大幅改善均匀编码，U_MinMax 的 2-bit 误差从 2.2919 降至 U_Clipped 的 0.5680，因此不能把未优化均匀范围造成的劣势全部归因于码点结构。经过范围优化后，非均匀经验树在 3/4-bit 仍更有优势；新增等宽嵌套与残差方案没有改变主候选的领先组合。

K 的 output-Jacobian 目标比简单 score 敏感性更值得保留；V 的目标则需要折中，混合普通 MSE 与 attention 权重优于一味集中于 attention 权重。上述训练仍采用可分离代理，并非直接优化完整 attention 或任务 loss。

**指标边界：** 相对 L2 为局部输出差值范数相对参考范数的比例，不是任务准确率下降比例。4-bit 时，Jacobian_Tree 相对 L2 优于 Data_Tree，但绝对 MSE 分别为 0.00684394 和 0.00612783，后者更低。因此“最好”必须限定指标；JacK_MixV 的结论限定于已统一汇总的平均相对 L2。

**存储口径：** 完整 8192-token、36 层、8 KV heads 配置的 4-bit payload 为 288 MiB；Data/Jacobian Tree 的编码附加状态约 336.5 KiB。KVarN 使用不同的局部均衡与元数据，部分历史条件还保留 FP16 尾部；独立三精度参考同时保存需要 9-bit。这些结果可作诊断对照，不能混入同条件主排名。

## 4. Controller 回放：主要收益来自 Query 引导

本轮固定**原始 Jacobian_Tree**，未使用编码侧领先的 JacK_MixV，以避免同时改变编码和策略。K 阶段只使用当前 Q 与冻结校准曲线；读取 K 后得到重建 attention，再决定 V 的读取深度。策略不接收完整当前 FP16 KV、真实输出或未来 Query。

四策略分别为均匀分配 uniform、仅校准曲线 static、仅当前敏感性 query_only，以及当前敏感性结合实测校准曲线 query_curve。K/V 两侧预算独立固定，并计入逐行字节填充成本。

|平均每侧读取位数|uniform MSE|static MSE|query_only MSE|query_curve MSE|
|---|---:|---:|---:|---:|
|2|0.2192508|0.2192508|0.2192508|0.2192508|
|2.5|0.1569187|0.1320655|0.0691433|0.0662326|
|3|0.0714867|0.0843731|0.0422947|0.0410364|
|3.5|0.0497458|0.0433816|0.0299124|0.0302988|
|4|0.0251012|0.0251012|0.0251012|0.0251012|

3-bit 下，query_curve 相对 uniform 的 MSE 降低 **42.60%**，请求配对 95% CI 为 [40.86%, 44.30%]；相对 query_only 降低 **2.98%**，区间为 [1.28%, 4.67%]。说明当前查询引导贡献了主要收益，实测失真曲线提供较小的增量。

增量并非所有预算均成立：3.5-bit 时，query_curve 比 query_only 的 MSE 高约 1.29%。static 在 3-bit 也弱于 uniform，表明仅依赖校准失真不足以保证合理分配。

代理目前更适合做分配排序，尚不足以承诺绝对质量阈值。3-bit query_curve 的真实 V 误差／预测值中位数为 1.549，P95 为 8.822；跨 token 交叉项约占平均精确 V 误差的 81.57%（汇总均值之比）。后续需处理残差相关性与校准失配。

## 5. 在线闭环：平均改善，但请求间波动明显

在线 pilot 使用同一 Jacobian_Tree，FP16 prefill，量化 decode 输出实际传递至后续层和 token。六任务各取两个请求，共 12 条，每策略生成 64 步。

|策略|与 FP16 的 token 位置一致率|采样局部 MSE|64 步完全一致请求|
|---|---:|---:|---:|
|FP16|100.00%|0|12/12|
|完整 4-bit|51.04%|0.00650167|4/12|
|均匀 3-bit|38.15%|0.01698548|2/12|
|动态平均 3-bit|45.05%|0.00947770|3/12|

动态方案相比均匀方案，平均一致率增加 **6.90 个百分点**，采样局部 MSE 均值低约 **44.20%**。但按 token 一致率逐请求比较，仅 3 条改善、3 条退化、6 条持平；一致率差的探索性配对 bootstrap 95% CI 为 [-13.41, 29.04] 个百分点，跨过零。

例如 qasper/16 的一致率由 1.56% 升至 100%，而 gov_report/46 从 100% 降至 35.94%。这些结果支持继续验证动态分配，但尚不能证明稳定的任务收益。

token 位置一致率衡量生成轨迹相似程度，不等于答案正确率。在线局部 MSE 使用各策略自身分支的当前输入作 FP16 shadow 对照，各分支输入已经不同，因此 44.20% 不能解释为完整模型输出误差的同输入配对下降。

## 6. 当前成果与后续工作

当前已完成从编码筛选、受限信息下的同预算决策，到量化误差跨层传播的验证链条。证据最充分的是局部编码质量和 controller 回放收益；在线任务效果仍属探索性证据。

|优先级|下一步工作|目的与主要对照|
|---|---|---|
|高|扩大独立请求，采用自然结束的完整生成及官方任务评分|保留 FP16、full4、uniform3、query_curve3；检查逐任务与尾部退化|
|高|诊断 V 跨 token 交叉项、校准曲线失配|验证代理能否用于质量阈值控制，而不只用于排序|
|中|单独验证 JacK_MixV 与 controller 的组合|固定策略比较编码，再固定编码比较策略，确认收益能否叠加|
|中|实现真实位平面存储、读取及 attention 路径|测量包含分配与两阶段读取的总延迟、真实流量及容量|

当前在线适配器保留 FP16 源缓存、重算码字并模拟前缀读取，其耗时和显存数据不代表部署性能。现有实验还存在单模型、测试集被后续设计复用、在线样本少且仅生成 64 步等限制。后续结论应以独立数据和完整任务质量为依据。
