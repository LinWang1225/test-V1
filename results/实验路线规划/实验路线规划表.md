# 基于创新方案的实验路线规划

依据：261023 (2).docx。以下为建议实验设计，非已经取得的结果；按单张RTX 3090、Qwen3-4B、原生KVarN INT4起步，周期约12周，需按开发资源调整。

主线：基线 → 编码正确性 → 逻辑读取预算 → V控制器 → K控制器 → 联合预算 → 编码/元数据筛选 → 物理访存 → 在线融合 → 端到端 → 消融。先用最简编码证明算法价值，物理布局只做小规模可行性检查，避免过早投入完整工程。

## 统一验收口径

- 质量：原生KVarN INT4为主参照，同时保留FP16。可预设各任务主要指标绝对下降不超过1个百分点作为初始讨论值（指标按0—100归一化）；该数值不是文档结论，正式容差应结合基线波动预先确定。小样本任务同时报告置信区间，不能仅凭“差异不显著”声称等效。
- 预算：总缓存字节 = Anchor + 全部Residual + Scale/Zero Point + 原有必要信息 + 新增元数据 + 对齐padding。完整4-bit都保留时，即便只读2-bit，也不是2-bit存储；若预算超限，明确归入额外存储方案，不能宣称严格等预算。
- 读取：分别报告逻辑位数、L2访问与实际DRAM读字节。元数据、控制器和额外临时buffer流量都计入。
- 性能：固定工作负载、预热、多次重复（建议至少3次）；主性能结果关闭profiler，profile另跑。明确TPOT定义、聚合方式与实际生成token数，固定长度实验单列。
- 决策：先看同等读取预算下的质量，再看同等质量下的DRAM流量和端到端时延；oracle仅解释潜力，不能当作可部署结果。
- 优先级：最小闭环为2+2编码、Midpoint重建、K4+动态V、单遍控制、融合attention。3-bit、条件均值、动态K、联合预算及新增元数据按证据逐步添加；新量化器和多位宽通用化留作扩展。
