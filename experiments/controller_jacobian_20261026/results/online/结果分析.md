# Jacobian 编码在线闭环试验分析

12 条请求、每策略 64 步的闭环 pilot 已完成。动态平均 3-bit 相比均匀 3-bit，平均 token 位置一致率从 38.15% 提高到 45.05%，增加 6.90 个百分点；采样局部 MSE 均值从 0.01698548 降至 0.00947770，低约 44.20%。但逐请求为 3 条改善、3 条退化、6 条持平，不能据此宣称稳定的任务质量收益。

## 在线与回放有什么区别

同样固定原 Jacobian_Tree、首校准种子。六任务各取冻结测试清单第一条和最后一条，共 12 条，使用原上下文；prefill 为 FP16。decode 的全部 36 层都用当前策略的量化 attention 输出，结果实际传给下一层和后续 token。每种策略独立生成，因而会形成不同的 Query 和缓存轨迹。

这与单层回放不同：回放将当前局部输出与同一 FP16 输入下的结果配对，但不让其改变生成；在线试验则观察误差如何影响整个后续计算。FP16 分支必须逐 token 复现旧冻结轨迹，该检查已通过。controller 仍只看当前 Q、校准曲线和重建 attention，不看未来 token 或原始完整 attention。

## 策略与整体结果

full4 完整读取 Jacobian K4V4；uniform3 每个单位读取 3-bit；query_curve3 在 K/V 各自平均 3-bit 预算内动态选择 2/3/4-bit。实际码字完整存储 4-bit。采样局部 MSE 在 decode 1/8/32/64 测量，同样先在请求内汇总。

|策略|与 FP16 的 token 位置一致率|采样局部 MSE|64 步完全一致的请求|
|---|---|---|---|
|fp16|100.00%|0.00000000|12/12|
|full4|51.04%|0.00650167|4/12|
|uniform3|38.15%|0.01698548|2/12|
|query_curve3|45.05%|0.00947770|3/12|

完整 4-bit 的平均一致率更高，是本轮有用的精度参考。动态 3-bit 在相同名义 payload 读取量下改善均匀 3-bit 的平均结果，但仍没有达到 full4 的平均一致率；这一观察支持继续研究分配，并不说明 3-bit 能普遍替代完整读取。

## 请求差异与统计不确定性

|请求|完整 4-bit 一致率|均匀 3-bit 一致率|动态平均 3-bit 一致率|
|---|---|---|---|
|longbench/gov_report/37|9.38%|9.38%|9.38%|
|longbench/gov_report/46|100.00%|100.00%|35.94%|
|longbench/hotpotqa/108|32.81%|32.81%|32.81%|
|longbench/hotpotqa/22|45.31%|10.94%|45.31%|
|longbench/lcc/248|100.00%|29.69%|14.06%|
|longbench/lcc/288|18.75%|18.75%|1.56%|
|longbench/passage_retrieval_en/14|100.00%|53.12%|100.00%|
|longbench/passage_retrieval_en/33|35.94%|35.94%|35.94%|
|longbench/qasper/16|1.56%|1.56%|100.00%|
|longbench/qasper/198|51.56%|51.56%|51.56%|
|longbench/trec/125|17.19%|14.06%|14.06%|
|longbench/trec/86|100.00%|100.00%|100.00%|

动态方案既有明显改善，也有退化。例如 qasper/16 从 1.56% 一致率提高到 100%，而 gov_report/46 从 100% 降到 35.94%。在这 12 条请求上，平均一致率差的探索性请求配对 bootstrap 95% CI 为 [-13.41, 29.04] 个百分点，区间跨过零。这个补充统计只用于说明小样本不确定性，不是预注册的任务显著性检验。

位置一致率比较相同生成位置的 token。一次早期分歧会改变后续上下文，即使两个分支生成同义但措辞不同的答案，也会拉低一致率；相反，一致率高也不能证明答案正确。它适合诊断轨迹稳定性，不是官方任务准确率、语义相似度或答案质量评分。

采样局部 MSE 也需限定解释：每个策略的局部 FP16 shadow attention 使用该策略当前分支的 Q/K/V 输入，而不是从头全 FP16 生成的同一隐藏状态。因此跨策略的局部均值并非同输入配对测量，更不能作为完整模型输出误差下降 44% 的证据。

## 为什么现在还不能报告速度或显存收益

参考适配器保留 FP16 源缓存，每步重算冻结码字并模拟前缀选择，还包含 CPU 分配、数据同步和 PyTorch 中间张量。它验证因果决策及跨层传播，不是部署用压缩缓存内核。保存的墙钟、TPOT 与峰值显存只反映该适配器开销，不能推出实际 HBM 流量、容量或服务加速。

本轮只生成 64 步，尚未做官方任务评分。下一阶段应保留 uniform3、query_curve3、full4 和 FP16 四个对照，增加自然结束的完整生成与官方任务指标，并在独立数据上检查均值、尾部与逐任务退化；质量证据稳定后再评估真实位平面内核的总延迟。
