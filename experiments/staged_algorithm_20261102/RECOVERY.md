# 断电与断点恢复

服务器恢复后，在项目根目录执行：

```sh
.venv/bin/python scripts/resume_staged_experiment.py
```

该命令不依赖旧PID。内核文件锁避免重复队列，断电后锁自动释放。后台运行日志追加到`logs/stage1_queue.log`，阶段状态和当前请求状态分别保存在`stage_status.json`、`worker_status.json`。当前是手动重启入口，不宣称已安装开机自启服务。

已完整保存的题目校验样本和运行指纹后跳过；评分也校验生成文件哈希并跳过已有有效评分。队列从第一个未完成方案继续，而不是从头重跑全部实验。源码、码本、样本或配置不匹配时停止，不能静默混用不同版本。

正在生成的题目每256个输出token保存前缀。恢复时从原始输入确定性重放该前缀，重新构建FP16 KV、整数码和Controller状态，逐token验证与保存前缀一致，再继续生成。由于没有把GPU KV缓存完整写盘，前缀重建需要计算时间；上次保存后至断电之间最多255个token需要重新生成。逻辑账本按完整生成轨迹计一次；结果注明重放token数，参考恢复耗时不作为服务性能指标。

结果和前缀JSON先写临时文件、flush/fsync，再原子替换并fsync父目录。中断留下的临时文件不是完成证据。原生上下文触顶有独立状态，不以断点恢复为理由增加短输出上限。

恢复使用相同本地环境、模型revision和外部数据源。GitHub备份不包括项目目录之外的模型权重与数据归档；本目录中超过GitHub单文件上限的文件列在备份排除清单，不能把代码备份描述成完整机器镜像。
