# 分阶段算法与工程实验协议

本轮按用户2026-11-02要求执行，独立保存，不覆盖旧实验。算法阶段使用逻辑读取量，工程阶段才验证位平面实际少读、DRAM流量和服务速度。参考实现保留uint8码与FP16源KV，其显存和耗时不作为压缩部署收益。

## 数据与生成

每方案使用同一464条：HumanEval全集164、MATH-500按subject×level比例分层固定抽样100、LongBench原版21子任务分层抽样合计200。11子任务10条、其余10子任务9条，额外配额用种子20261102固定；各任务按完整prompt token长度四分层抽样。排除60条编码校准请求；历史探索重叠单列。不把反复用于选方案的面板称为全新独立测试。校准仅用历史60条激活，不使用测试答案。

冻结原始ID、版本、source_index、prompt与token哈希。完整prompt重新分词，不继承旧实验的首尾截断；原生上下文容纳不下的LongBench输入在抽样前排除并记录。所有方案输入一致。

模型Qwen3-4B，revision 1cfa9a7208912126459214e8b04321603b3df60c；贪心、enable_thinking=False、自然EOS；不设2048/8192等人为输出上限、不采用LongBench逐任务短输出上限、不按FP16输出长度停止。模型原生上下文上限是运行边界，触及边界记native_context_limit，保留完整输出与评分并单列完成率。OOM、推理异常保留现场并停止队列，不能跳过样本伪造完成。运行中每256输出token持久化保存前缀；重启校验后跳过完整请求，对未完成请求确定性重放已保存前缀以重建KV，再继续生成。恢复入口与运行边界见RECOVERY.md。

Prefill各方案FP16，decode全36层闭环使用对应KV重建；统一每512 token prefill分块。关注存储已有KV与未来query间的错配，不改变原模型权重。HumanEval官方隔离执行评分、MATH官方等价判分、LongBench官方逐任务指标沿用冻结vendor代码。取消输出上限属于修改生成协议，旧质量结果不得直接混入本轮比较。

## 阶段与依赖

1. **编码与曲线**：Hadamard-sign固定，依次运行FP16和Gaussian_Tree、Data_Tree、Jacobian_Tree、JacK_MixV、U_Clipped的full4端到端464条。保留重建精度0/1/2/3/4。随后比较同一编码的固定整数深度及参考Controller的曲线消融。full4结果不是完整动态读取方案的排名；最终编码选择还需查看共同Controller下的质量—逻辑读取量。先验证支持候选，不把局部相对L2赢家当任务质量赢家。
2. **基底**：编码结构固定，对Identity、Hadamard-sign、KLT、DCT使用相同校准数据与拟合预算；先分别K/V再组合。无量化等价检查先行，明确post-RoPE K与Q同步变换、V输出逆变换。重新拟合参数，不能直接换U沿用Hadamard码本。该阶段在编码报告审查后执行。
3. **Controller**：编码与基底固定，比较固定逻辑预算及误差容忍度驱动非固定预算，统一读取单位。预算档位整数0/1/2/3/4；各单位整数深度，实际元素加权平均可为小数。阈值不得从464条测试分数反向挑选。需要另行冻结与校准不重叠的验证请求确定阈值；当前预置0.05仅用于实现与探索，不构成质量保证。
4. **工程**：算法证据成立后开发真实位平面打包与选择性加载，验证重建等价，测实际DRAM读写、元数据访问、总延迟、容量和吞吐。若更改读取单位或策略则重跑受影响的Controller比较；无损布局变更不用重复全部编码筛选。

当前启动队列只自动完成第1阶段的FP16及五种full4编码基线，不在结果未完成时自动宣布赢家或跨阶段换基底。阶段状态见stage_status.json。

## 0～4-bit与读取单位

同一个4-bit码字高位前缀重建，不独立重编码。旧2/3/4-bit表保持冻结；1-bit表按已有MSB的两个分组，在同60条bootstrap校准数据上拟合条件标准化均值，保存FP16；0-bit重建为已有离线校准mean，不删除token、不屏蔽K score、不改变softmax token集合。0-bit不读取payload，但mean等元数据仍有成本。

K读取单位为128-token block×物理KV head×channel，V为物理KV head×token的128个通道；所有曲线策略统一此粒度。K尾块按有效token数计逻辑成本。GQA的4个Query heads重要性合并。算法阶段不计尚未实现的事务对齐，不称为真实字节。固定预算是每侧payload上限，不要求必须消耗无益位数；当前实现为保前置依赖的边际收益/逻辑成本贪心，前缀预算选择可能剩余预算，不保证一般非凹情况下全局最优，报告实际消耗和曲线违反情况。

## 曲线与元数据消融

物理尺度D(c,b)=E[(X_c-Xhat_c(b))²]，保存0～4五点。其已含scale²，Query敏感性加权时不得再次乘scale²。编码拟合权重与Controller曲线是两件事。

- query_only：当前Query/phat，使用统一理论下降形状，不使用经验D。
- global：当前Query/phat×离线逐通道平均D。
- shared/head：保留通道D0幅度，分别共享每侧或逐head归一化曲线形状，分离幅度和形状贡献。
- scale：Dhat(j,c,b)=r(j,c)D(c,b)。r为当前block相对离线mean的二阶矩除以校准D0，写入时计算，FP16保存。主动尾块随追加更新，旧完整块不重复计算；额外统计计算和写入单列。单比例修正不能默认校正各深度形状。
- jacobian：使用校准Output-Jacobian/attention权重归一化的逐通道误差J；J=E[w e²]/E[w]。K权重来自冻结校准attention output Jacobian，V来自校准attention²。测试仍用当前Query/phat；其可能重复某些敏感性因素，只作为待验证代理，不称为真实当前Jacobian。
- scale_jacobian：局部scale与校准功能权重交叉，检查二者是否互补。
- delta_fp32/delta_fp16：存四段Δ0→1、Δ1→2、Δ2→3、Δ3→4。固定预算选择只需要收益；绝对误差恢复需D4锚点。参考实现保留D4锚点便于统一接口，但容量报告须同时给出纯收益与收益+锚点，不把五点变四段+锚点称为节省。专门的2～4消融只需两段收益，相比三点省1/3原始数组容量；不得把这一比例外推到0～4。
- local_gain_fp16：在KV写入时测当前block各前缀误差，保存四段局部收益作为较高信息量诊断。没有未来Query；Controller不重新访问FP16 KV。其计算、更新和元数据成本必须单列，不自动作为轻量方案。V决策为block曲线展开到token的近似，非逐token真实误差。

训练得到的完整局部曲线仅可作评估诊断，不将测试真实Attention或答案输入决策。当前实现的局部gain用于相对full4风险，不提供绝对D4。固定与非固定比较必须采用同一代理定义；非固定目标是每侧相对full4的总代理额外风险容忍量，不是任务质量或真实输出误差上界。

检验局部修正对真实重建误差的预测、边际收益排序、Attention输出误差、K score与softmax误差以及最终任务质量。局部scale是否改善形状、Jacobian是否改善风险排序均由实验判断；V跨token交叉项及K/V交互不被对角代理精确覆盖。

## 统计与完成标准

每请求逐次累加sum_i N_i*b_i，K/V分开，0-bit正确记零payload，FP16记16-bit；完整生成逻辑总量、每输出token逻辑量、访问元素加权平均、各深度元素数、自然EOS率、上下文触顶率、生成长度和官方质量均保留。不能用各自轨迹full4分母的比例代替相同工作量硬件节省。

码本、mean/scale、全局曲线、Jacobian曲线、局部统计、位宽决策状态分别报告。列出实际参考张量/文件容量与拟部署表示容量，两者不得混称；参考LUT展开和FP16源缓存明确标注。全局状态驻留容量、局部状态峰值、更新写入量、每调用解析访问allowance分别统计，allowance不是DRAM。比较payload预算相同及payload+元数据总成本相同两个口径；共享全局状态不按每请求复制容量。

HumanEval、MATH、LongBench各子任务分别报告，LongBench宏平均声明为辅助指标，不把464条不同任务分数混成准确率。请求配对bootstrap置信区间与逐题得失、输出长度变化保留。非EOS输出按相同评分器评分，同时单列未自然完成子集，不能筛掉失败样本抬高分数。缺失结果留空，未知评分错误停止并保留证据。
