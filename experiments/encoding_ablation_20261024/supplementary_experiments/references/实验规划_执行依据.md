我建议把下一轮工作定义为：**面向 K/V 对称存储、多精度重建的补充消融实验**。

核心是回答三个问题：

1. **均匀嵌套量化与非均匀嵌套量化，哪一种更适合 2/3/4-bit 渐进式重建？**
2. **在 K/V 粒度和最终存储精度完全相同的条件下，使用不同优化目标能带来多大收益？**
3. **新的编码是否具有更好的失真曲线和边际收益，从而更适合后续动态读取精度分配？**

下面按可直接交给 Codex 执行的顺序整理。

## E1：均匀嵌套量化 vs 非均匀嵌套量化

<badge color="info">最高优先级</badge>

这是下一轮必须补充的核心实验。

目前已有 A/B/C/D 四种方法，但原来的 A 使用校准最小值、最大值确定均匀量化范围，容易受到异常值影响。

如果直接用 A 对比 C，很可能把“量化范围选得不好”误认为“均匀量化本身不好”。

因此建议增加一个优化截断范围的均匀量化器。

| 编号 | 编码方法 | 具体方案 | 实验目的 |
|---|---|---|---|
| E1-1 | U-MinMax | 原 A，均匀 INT4，2/3-bit 用前缀区间中心重建 | 保留原始基线 |
| E1-2 | U-Clipped | **新增**，在校准集上选择较优截断范围，再进行均匀嵌套量化 | 排除极值对均匀量化的不公平影响 |
| E1-3 | Gaussian Tree | 原 B，ReadKV 风格递归 Gaussian Lloyd 量化树 | 作为理论分布先验基线 |
| E1-4 | Data-adaptive Tree | 原 C，真实分布驱动的嵌套 K-means 量化树 | 比较数据自适应非均匀量化 |

具体比较三个问题：

**问题 A：** 在完整 4-bit 时，非均匀量化能否明显降低误差？

**问题 B：** 在 2/3-bit 前缀下，非均匀量化是否仍具有优势？

**问题 C：** U-Clipped 是否可以接近非均匀编码效果，并且具有更低的编码、解码复杂度？

建议增加的指标：

- K/V 原始 MSE、相对 L2。
- Score RMSE、Attention Probability L1。
- Attention Output 相对 L2。
- 2/3/4-bit 失真曲线。
- 2→3、3→4-bit 的边际收益。
- 码本大小、编码耗时、解码耗时。
- 各级码字分布、码字利用率。
- 4-bit 前缀编码正确性。

还有一个很重要的辅助对照：分别训练独立的 2-bit、3-bit、4-bit 量化器，作为各精度下的参考上限。

它们不能作为渐进编码的正式基线，因为需要分别存储编码，但可以衡量：

> 为了实现嵌套读取，相比独立最优量化器，究竟损失了多少重建精度？

可以定义：

\[
P_b=\frac{D_b^{nested}-D_b^{independent}}
{D_b^{independent}}
\]

其中 \(P_b\) 越小，说明嵌套编码对该精度的牺牲越少。

## E2：K/V 优化目标非对称实验

<badge color="info">最高优先级</badge>

这一阶段所有方案继续使用**相同的量化粒度、4-bit 存储及嵌套结构**。

只替换训练损失函数。

| 编号 | K 的优化目标 | V 的优化目标 | 实验目的 |
|---|---|---|---|
| E2-1 | 普通 MSE | 普通 MSE | 基准 |
| E2-2 | Output Jacobian 加权 | 普通 MSE | 验证 D-K + C-V |
| E2-3 | Score-aware | 普通 MSE | 单独检验 K 的优化目标 |
| E2-4 | Score-aware | Attention 加权 MSE | 检验你提出的完整方案 |
| E2-5 | Score-aware | 普通与加权 MSE 混合 | 缓解 V 高精度退化 |
| E2-6 | Output Jacobian 加权 | 混合 MSE | 检验现有 K 优化方式是否更合适 |

其中 E2-2 应最先运行。

原因是原实验已经观察到：

- D 的 K-only 输出误差相比 C 明显下降。
- D 的 V-only 在 3/4-bit 时反而不如 C。
- 目前还没有验证 D-K + C-V 同时使用时的真实 Attention Output。

因此，先确认混合编码收益，再扩展损失函数会更高效。

### 增加一个交叉对照

建议让 E2-3、E2-4 至少分别在 U-Clipped 和非均匀嵌套树上执行一次。

这样才能判断：

**优化目标的收益是否依赖非均匀编码？**

否则如果只在非均匀编码上测试新的损失函数，最终无法区分收益到底来自编码结构还是训练目标。

## E3：多精度联合优化实验

<badge>第二优先级</badge>

你现在的 C 方法采用逐级分裂：

2-bit → 3-bit → 4-bit。

但还没有充分验证，是否应该在训练时同时考虑三个读取精度的最终表现。

建议比较：

| 编号 | 训练方式 | 主要区别 |
|---|---|---|
| E3-1 | 原始逐级分裂 | 沿用 C/D 方法 |
| E3-2 | 仅优化 4-bit | 重点追求最终完整编码精度，检查低精度前缀表现 |
| E3-3 | 2/3/4-bit 联合优化 | 同时降低三种读取深度的损失 |
| E3-4 | 联合优化 + 收益递减正则 | 检查是否能够改善动态精度分配条件 |

核心损失：

\[
\mathcal L_{\mathrm{prog}}
=\alpha_2D_2+\alpha_3D_3+\alpha_4D_4
\]

第一轮建议固定：

\[
\alpha_2=\alpha_3=\alpha_4=\frac13
\]

如果联合训练效果明显，再调整不同精度的权重。

E3-4 暂时不要投入太多复杂设计。只有在 E3-3 确认存在显著、实质性的收益递减违反时，再尝试加入约束。

这与 Any-Precision LLM 的嵌套精度思想相关，但你研究的是 KV Cache 的 Attention 目标与动态读取，而不是模型权重的多精度部署。<Cite ref="turn25search0"/>

<badge>第二优先级</badge>

先固定存储为 K4V4，比较读取：

- K2V2
- K3V3
- K4V4
- 相同平均读取预算下的动态 2/3/4-bit 方案

如果后续允许 K/V 分别选择读取深度，可以额外测试 K2V4、K3V3、K4V2 等，但这不改变 K/V 的最终存储精度。

| 编号 | 实验内容 | 观察指标 |
|---|---|---|
| E4-1 | 各精度失真曲线 | \(D_2,D_3,D_4\) |
| E4-2 | 2→3、3→4 边际收益 | \(\Delta_{23},\Delta_{34}\) |
| E4-3 | 收益递减违反分析 | 违反率、违反幅度、最差层 |
| E4-4 | 贪心分配 vs 精确 DP | 代理失真差距、计算成本 |
| E4-5 | 相同读取预算下比较不同码本 | Output Error、逻辑读取字节数 |

ReadKV 的贪心分配最优性依赖特定的可分离失真目标及收益递减条件。因此，这部分应针对**你实际用于分配的损失函数**重新验证，而不能只观察原始 MSE。<Cite ref="turn25academia12"/>

# 三、必须补充保存的实验记录

我建议这次把记录体系分成四类，而不是只在最后生成一个平均误差表。

## 1. 失真曲线：最重要

对每个方法保存：

\[
\boxed{D(2),D(3),D(4)}
\]

需要分别记录：

| 曲线 | 定义 | 作用 |
|---|---|---|
| K 原始重建失真 | \(D_K^{MSE}(b)\) | 看量化本身的精度 |
| V 原始重建失真 | \(D_V^{MSE}(b)\) | 看 V 数值重建质量 |
| K Score 失真 | \(D_K^{score}(b)\) | 验证 Score-aware 编码 |
| V Attention 加权失真 | \(D_V^{attn}(b)\) | 验证 V 权重设计 |
| Attention Output 失真 | \(D_O(b_K,b_V)\) | 衡量最终功能误差 |

这里要注意：K/V 优化目标不同，其损失的绝对数值不能直接横向比较。

但可以分别比较同一个目标下不同编码器的失真曲线。

## 2. 边际收益：必须保留原始值

对于每条失真曲线：

\[
\Delta_{23}=D(2)-D(3)
\]

\[
\Delta_{34}=D(3)-D(4)
\]

建议同时记录：

| 字段 | 说明 |
|---|---|
| `D2` | 2-bit 失真 |
| `D3` | 3-bit 失真 |
| `D4` | 4-bit 失真 |
| `gain_23` | 2→3-bit 收益 |
| `gain_34` | 3→4-bit 收益 |
| `gain_ratio` | \(\Delta_{34}/(\Delta_{23}+\epsilon)\)，仅在分母为正时解释 |
| `negative_gain` | 增加精度后失真反而上升 |
| `diminishing_violation` | 是否违反收益递减 |
| `violation_magnitude` | 违反程度 |
| `layer` | 层编号 |
| `head` | KV Head |
| `unit_type` | Channel 或 Token |
| `method` | 编码方法 |

建议定义归一化的违反幅度：

\[
V=
\frac{\max(0,\Delta_{34}-\Delta_{23},-\Delta_{34})}
{D_2+\epsilon}
\]

它可以帮助区分：

- 违反率较高，但违反幅度几乎为零。
- 违反率不高，但少数位置有严重的非单调行为。

后者可能对动态分配更危险。

此外建议同时使用绝对和相对数值容差，保存判定阈值。

你原实验的 DP 存在 float32 精度引起的微小差距，这次建议**全部用 float64 复核 DP 与贪心差距**。

## 3. 码本与编码信息

这一部分容易被忽略，但对后续研究新编码方式非常重要。

| 内容 | 建议保留的数据 |
|---|---|
| 码本结构 | 2/3/4-bit 每级质心和分裂关系 |
| 编码阈值 | 各节点决策边界 |
| 码字分布 | 16 个叶码字使用频率 |
| 前缀利用率 | 2-bit 四个前缀、3-bit 八个前缀的频率 |
| 聚类情况 | 空簇数量、有效簇数量 |
| 量化范围 | Min、Max、Clip 阈值 |
| 归一化 | Mean、Scale、旋转配置 |
| 训练信息 | 损失函数、权重配置、收敛迭代 |
| 元数据 | 每层、每 Head 的额外字节数 |

这些记录可以回答一个更深入的问题：

**非均匀量化的优势究竟来自更合适的分布拟合，还是来自让重要样本获得更小的量化误差？**

例如，当 C 在某层的收益很大时，可以检查该层码字分布是否明显非均匀，以及重要区域的重建误差是否下降。

## 4. 分层、分任务和硬件相关数据

| 层级 | 必须保存的指标 |
|---|---|
| Request | 输出误差、任务名、输入长度 |
| Layer | 每层 2/3/4-bit 误差、相对改善 |
| Head | K/V 失真、边际收益统计 |
| Decode step | 位置 1/8/32/64 的指标 |
| Attention | Score RMSE、Probability L1、Output L2 |
| Storage | 4-bit payload、码本元数据、总字节 |
| Reading | 各 Plane 逻辑读取字节、平均读取深度 |
| GPU（后续） | HBM 读取量、Kernel 延迟、TPOT、吞吐量 |

对于已有结果中“4-bit D 仅在 18/36 层优于 C”的现象，下一轮尤其需要记录：

- 每层的平均收益；
- 最差层退化；
- 哪些 Head 存在明显退化；
- 退化是否集中在某一读取精度。

## 最终建议

这次补充实验最值得形成的三组主结论是：

1. **编码方式：** 均匀嵌套与非均匀嵌套，谁在相同 4-bit 存储下提供更好的 2/3/4-bit 重建质量？
2. **编码目标：** K/V 使用不同的 Attention-aware 目标，能否在不改变存储粒度和位宽的情况下进一步降低输出误差？
3. **渐进特性：** 新的编码是否不仅降低失真，还能改善边际收益曲线，使后续动态读取更加有效？

这三点分别对应你潜在论文中的**编码结构、K/V 功能感知优化、多精度读取适配**。

其中我尤其建议把**失真曲线、边际收益分布、收益递减违反幅度和 Error–Read Bytes 曲线**列为必交付结果。它们既能解释当前编码为什么有效，也能为下一步动态精度 Controller 提供直接依据。
